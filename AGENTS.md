# Instructions for coding agents

- Follow the project scope and stack in `README.md`: a single-player desktop browser game using HTML, CSS, vanilla JavaScript and Canvas. Keep listed features planned until implemented.
- Make small, focused changes. Do not add dependencies or features beyond the approved scope without asking first.
- Explain each change in beginner-friendly language, including what changed and why.
- After each gameplay change, give me a specific manual check I can perform. Do not say it passed unless I actually report the result.
- Never claim a test passed unless you ran it and observed the result. Be clear when something was not tested.
- Use Medium as the starting reasoning setting for routine development and documentation. Higher reasoning effort may be used for difficult debugging or deeper review. Do not change model or settings automatically, and do not claim higher effort guarantees correctness.
- Record the actual model and reasoning setting when known; do not guess unknown identifiers. Distinguish user-reported manual checks, agent-run tests, and code review.
- Describe only files and commands that actually exist. The project has `README.md`, `PLANS.md`, `AGENTS.md`, `index.html`, `style.css` and `game.js`. Open `index.html` in a desktop browser to launch it.
